## This repo: fsbhoa_ac_core

The **core WordPress plugin**, plus one Go backend service (`monitor_service`).

## PHP plugin structure

- `fsbhoa-ac-core.php` — entry point; `require_once`s every module explicitly (no autoloader). New files must be added here. Handlers are instantiated in three places: `run_fsbhoa_action_handlers()` on `init` (AJAX/`admin_post_` action classes), `fsbhoa_ac_api_init()` on `rest_api_init` (REST classes call `register_routes()`), and `is_admin()` / front-end blocks.
- `includes/<module>/` — per-feature modules, each typically a `*-admin-page.php` (rendering, often a `WP_List_Table`), a `*-actions.php` (form/AJAX handlers registered in the constructor), and `views/` templates.
- The UI is primarily **front-end pages rendered via shortcodes** (`includes/class-fsbhoa-shortcodes.php`: `[fsbhoa_cardholder_management]`, `[fsbhoa_live_monitor]`, `[fsbhoa_vendor_management]`, etc.), which is why `WP_List_Table` is loaded outside admin. The site forces login for all front-end pages.
- REST routes: `/monitor/*`, `/reports/*`, `/test/*`, `/access/*`.
- JS/CSS per module in `assets/js`, `assets/css`; third-party libs (jQuery UI, DataTables, Chart.js, Croppie, Tailwind) are vendored in `assets/vendor`.
- Cron scheduling for the nightly rebuild / daily time sync is in `fsbhoa_schedule_cron_jobs()` in `fsbhoa-ac-core.php`.

### Schema changes — keep three files in sync
- `includes/class-fsbhoa-core-repository.php` → `create_tables()` (runs on activation; `CREATE TABLE IF NOT EXISTS`)
- `db_schema.sql` — phpMyAdmin dump of the current schema (reference)
- `migration.sql` — script to upgrade the production DB to the new release

## Go monitor service (`monitor_service/`)

WebSocket hub (gorilla/websocket) for the live monitor. Endpoints: `/notify` (events in), `/update-gate-status`, `/ws` (browser clients). Reads `/var/lib/fsbhoa/monitor_service.json` (`-config` flag), which is generated by `includes/admin/class-fsbhoa-ac-settings-page.php`.

## Commands

```bash
./rebuild.sh            # build Go service(s) -> monitor_service/fsbhoa_monitor
./rebuild.sh install    # build, copy to /usr/local/bin, restart systemd fsbhoa_monitor
cd monitor_service && go build ./... && go vet ./...
php -l path/to/file.php # syntax check (no PHPUnit/linters configured)
sudo systemctl status fsbhoa_* --no-pager
```

`TEST_PLAN.md` is a manual test plan, and there is an in-app Test Suite page (`includes/admin/class-fsbhoa-test-suite-*`). `rebuild.sh` is for rebuilding this plugin's services on the dev machine. `deploy_monitor.sh` (and `/home/pi/deploy-production.sh`) were early attempts at production deployment and are out of date; the deployment process is due to be redesigned, so don't rely on them.
